## 2. Аудит: что в Engine есть и чего нет

Бриф исходит из того, что в Engine уже есть `ImmersiveStage`, `BeatController`, камера, таймлайн, маски, аннотации, пост-обработка и `sites/`. **На `main` ничего этого нет.** Проверено по дереву `src/`:

| В брифе | В репозитории |
|---|---|
| `sites/` | нет; инстансы лежат в `src/config/verticals/<slug>/` |
| `src/components/wow/webgl/stage`, `ImmersiveStage` | нет; есть только `WebGLImageLayer`: градиентная текстура с параллаксом по скроллу |
| `BeatController`, timeline, camera | нет; motion — это `Reveal`, `Parallax`, `PinnedScroll`, `HorizontalScroll`, `Crossfade` |
| маски, blur, exposure, magnifier, DOM-аннотации | нет |
| post-processing (grain, vignette) | нет |
| reduced motion | есть: `useMotionCapability()` |
| WebGL fallback | есть, в `WebGLImageLayer` |
| `resolveAsset` | есть |
| реестр секций, валидация, preview | есть |

Модель Engine — **вертикальная лента секций**: `SiteConfig → PageRenderer → SectionRegistry → Section`. Прототип устроен иначе: **одна сцена, 13 битов, один жест — один кадр**, слои живут на общем прогрессе `p`. Собрать это из существующих секций нельзя, не изменив дизайн. Поэтому нужна одна новая generic-возможность (§4).

Во Flowerstim (`florist`) стоят те же секции, шесть из десяти — заглушки (`return null`). Переиспользовать там нечего, кроме инфраструктуры: типов, resolver-ов, валидации, preview.

## 4. NEW ENGINE CAPABILITY: `immersive-stage`

**Зачем нужна.** Дизайн — это непрерывная сцена с пошаговыми битами, боковым переходом камеры между вкусами, затемнением между главами, курсорным параллаксом по глубине и подписями, привязанными к точкам кадра. Ни одна существующая секция и ни один motion-примитив этого не умеют. Если собрать из `PinnedScroll` и `Crossfade`, получится обычная scroll-анимация, а бриф её прямо запрещает (§8).

**Что добавить в core.** Всё generic, без имён бизнеса:

1. `src/lib/types/stage.ts` — есть в пакете. Экспортировать из `src/lib/types/index.ts`.
2. `src/lib/types/section.ts` — добавить `"immersive-stage"` в `SECTION_IDS`.
3. `src/components/wow/stage/`:
   - `useBeatController.ts` — ввод и переходы между битами (§7);
   - `interpolate.ts` — `prep`/`at`/`atO` (§6);
   - `ImmersiveStage.tsx` — рендер слоёв, rAF-цикл, HUD, аннотации, вуаль, зерно.
4. `src/components/wow/sections/index.ts` — экспортировать `ImmersiveStage` и `ImmersiveStageProps`:
   ```ts
   interface ImmersiveStageProps {
     choreography: StageChoreography;
     variants: StageVariant[];
     copy: StageCopy;
     assets: AssetManifest;
     theme?: ThemeTokens;
     motion?: MotionConfig;
   }
   ```
5. `src/lib/render/section-registry.ts` — `"immersive-stage": { default: ImmersiveStage }` плюс запись в `SectionPropsMap`.
6. `src/lib/validation/validate-assets.ts` — добавить `"immersive-stage"` в `SECTIONS_REQUIRING_MEDIA`. Опционально: проверка, что каждый `layer.media` и `layer.video` резолвится.
7. `src/config/preview-registry.ts` — `{ slug: "kuki-luki", label: "Куки Луки — Immersive", config: kukiLukiSiteConfig }`.

**WebGL.** Прототип собран на DOM-слоях: `translate3d` / `scale` / `filter: blur` / `mask-image` / `<video>`. Всё это композитит GPU. Точно повторить дизайн можно тем же способом, и тогда отдельный fallback не нужен. Если перевести слои на three.js-плоскости, придётся заново писать blur, маски и видео-текстуры, а визуального выигрыша это не даст. Рекомендация для v1: `ImmersiveStage` на DOM. WebGL подключить позже для пост-обработки (зерно, хроматика), с fallback через уже существующий `isWebGLAvailable()`.

## 6. Математика движения

Всё в `choreography.ts`.

- **Keyframes.** `[p, {x,y,s,o,b,h}]`, незаданные поля наследуются от предыдущего ключа: `prep`, старт `{x:0,y:0,s:1,o:1,b:0,h:0}`. Внутри сегмента t = smoothstep(t₀) = t²(3 − 2t).
- **Opacity-треки.** `[p, o]`, smoothstep.
- **Transform слоя.** `translate(-50%,-50%) translate3d(x·vw + shift, y·vh, 0) scale(s)`. Слой центрирован в `left: 50%; top: 50%`.
- **Filter.**
  - blur: `min(8, round(b))` px;
  - дымка: `contrast(1 − 0.32h) brightness(1 − 0.12h)`;
  - hover: `brightness(1 + 0.08·hover)`.
- **Сглаживание.** Значение слоя догоняет цель: `c += (v − c)·(1 − e^(−10·dt))`. Курсор: `1 − e^(−4·dt)`.
- **Параллакс.** `x += ptr.x·depth`, `y += ptr.y·depth·0.6`, ptr ∈ [−1, 1], в px на vw-единицу.
- **Дыхание.** `y += sin(t·0.6 + variant·2)·0.35vh·breathe`.
- **Tween.** Длительность `750·(1 + min(0.6, |Δp|·1.5))` мс, easeInOutCubic.
- **Dip.** 825 мс. Вуаль smoothstep 0 → 1 → 0, прыжок в середине.
- **Slide.** 937 мс. `a = (t / 0.5)³` в первой половине, `(1 − (t − 0.5) / 0.5)³` во второй. `shift = ∓dir·a·105vw·(1 + depth / 60)`, прыжок в середине.
- **Портрет.** `innerWidth / innerHeight < 0.8` → берутся `keyframesPortrait`. Пересчёт на resize.
- **Зерно.** SVG `feTurbulence` baseFrequency 0.9, opacity 0.13, `mix-blend-mode: overlay`, случайный сдвиг ±30 px каждый кадр.

## 7. BeatController: ввод

Один жест — один бит. Это главное требование заказчика: трекпад и мобильный должны работать без пропусков и без двойных шагов.

- **Колесо и трекпад** (`passive: false`, `preventDefault`):
  - новый жест — пауза между событиями > 160 мс, или > 110 мс на битах вкуса;
  - либо «подъём» |delta| после затухания инерции:
    - обычные биты: ≥ 4 затуханий подряд и рост > 2.5× (минимум 24), не чаще раза в 350 мс;
    - биты вкуса: ≥ 2 затуханий и рост > 1.6× + 4 (минимум 10), не чаще раза в 200 мс;
  - шаг — когда накоплено |Σdelta| > 12; после шага жест «разряжен» до следующего.
- **Во время перехода** жест не теряется: ставится в очередь (один), очередь исполняется по завершении. Tween после 45% длительности принимает новый шаг сразу.
- **Тач.** Шаг, если |dy| > 40 px и |dy| > |dx|. `touchmove` — `preventDefault` вне меню.
- **Клавиши.**
  - вперёд: ↓, PageDown, Space;
  - назад: ↑, PageUp;
  - Home — первый бит, End — последний.
- **Меню.** Если жест над слоем `menu` и лист может скроллиться в эту сторону, жест отдаётся листу.
- `html` и `body` получают `overflow: hidden` на время жизни сцены.

## 9. Риски и открытые вопросы

1. **Ассеты сгенерированы по описаниям, а не по фото реальных печений.** Перед продом нужна пересъёмка в Higgsfield image-to-image по 3–4 фото каждого вкуса.
2. **Oreo и Kinder — чужие товарные знаки.** Проверить, что логотипы не читаются.
3. **Декор Киндера** — догадка. Нужен состав от клиента.
4. **Вырезка Киндера обрезана** на 20% сверху. У вырезок бывает розовая кайма от исходного фона, особенно заметно на молочной студии.
5. **Видео лежат на CDN Higgsfield.** Скачать в `public/sites/kuki-luki/` и перевести в H.264 + WebM с poster.
6. **`menuUrl`** — заглушка на Яндекс Карты, не подтверждена.
7. **`signature-cookie` без вырезки.** Держится на маске; для S06 на розовом этого достаточно.
8. **Reduced motion.** В прототипе отключаются только параллакс и дыхание. Переходы между битами остаются. Упрощать ли их дальше — решение за вами, в дизайне этого нет.
