# CLAUDE.md — сайт агентства «Есть что показать»

Этот файл читает Claude Code при работе в репозитории. Отвечай и пиши комментарии на русском.

## Что строим

Одностраничный сайт-история агентства «Есть что показать» (слоган: «Делаем видимым то, что у вас уже есть»). Это **sales experience**, а не портфолио: посетитель (владелец ресторана, салона, цветочного, пекарни…) должен за 7 экранов пройти путь «это про меня → есть способ лучше → они умеют → я ничем не рискую → оставлю заявку».

Формат: **один свайп / колесо / клавиша = один экран**, сильно анимированные переходы, mobile first. Драматургия построена как имя: первая половина — голос клиента («Вам есть что показать»), **поворот** на экране 04 — «Нам есть что показать вам», дальше наш голос, доказательства и форма.

**Эталон поведения и вида — рабочий прототип** `reference/prototype/index.html` (открывается двойным кликом, без сервера). Всё, что не описано в `docs/`, смотри в нём: вёрстка, тайминги, состояния. Снимки каждого экрана — `reference/screens/{mobile,desktop}/`.

## Рекомендуемый стек (если в репозитории ещё нет своего)

- **Vite + TypeScript, без фреймворка** (или Astro, если нужен SSR/SEO-шаблон). Сайт — одна страница со сценами, React не нужен.
- Анимации — CSS transitions/keyframes + небольшой контроллер сцен на TS (как в прототипе). GSAP — только если без него не обойтись.
- 3D / WebGL — **не сейчас**. Поворот в прототипе сделан на CSS/canvas/SVG. Позже его переносят на внутренний движок (Engine); архитектуру сцен держи так, чтобы сцену поворота можно было заменить модулем.
- Шрифты: **Geologica** (300/400/500/600) — основной; **Cormorant Garamond** — только внутри макетов сайтов в телефоне (кофейня, цветочный). Подключать локально (woff2), не с Google Fonts в проде.
- Если в репозитории уже есть стек — следуй ему, не меняй.

## Архитектура (как устроен прототип — повторить в модулях)

```
deck            — колода экранов .screen (8 штук: 01, 02, 03, 04 поворот, 05 цветы, 05 пекарня, 06, 07)
navigation      — свайп / колесо (с накоплением и блокировкой) / стрелки / PageUp-Down / кнопка «Дальше» / меню / точки справа на десктопе
film (фон)      — общий фоновый слой с состояниями data-film: street | hand | scroll | glow | open | done | calm | shade
                  street/hand — улица и рука с телефоном; scroll — поле одинаковых карточек (3D); glow — карточка «вашего места» выходит вперёд;
                  open → done — поворот: раскрытие из карточки → чертёж → каркас → готовый сайт в телефоне
acts            — фоны второго акта data-act: flow (цветы) | cook (пекарня) | city (06) | end (07)
mac             — вступление кейса «макро → пролёт насквозь»
sheet           — форма в нижней шторке
```

Состояние на корне `<html>`: `data-film`, `data-act`, `data-hero`, классы `s1p` (первый свайп на 01 сделан), `ready` (сцена договорила — стрелка «Дальше» оживает), `rm` (меньше движения).

## Жёсткие правила (нарушать нельзя)

1. **Технология невидима.** На сайте нигде нет слов WebGL, AI, Engine, Three.js, Claude, Higgsfield, «нейросеть». Никаких технических лоадеров и подписей.
2. **Без буквальной фото-метафоры:** плёнка, кадр, фокус-кольца, фотолаборатория.
3. **Без неона, киберпанка, крипто- и SaaS-эстетики.**
4. **Кейсы — концепты, не клиенты.** Цветочный магазин и кафе-пекарня — прототипы, сделанные для компаний, которые не подписали договор. Показывать **обезличенно**, с пометкой «Концепт», без цифр и результатов, без названий брендов, логотипов, адресов, рейтингов. Названия «Flowerstim», «Куки Луки», «Эстетика цветов», «Бутырская» в коде, текстах, alt и именах файлов — запрещены.
5. **Вымышленная «Кофейня на углу»** в сцене поворота — временное решение (отступление от решения №23 стратегии), ждёт подтверждения. Держи её отдельным заменяемым модулем.
6. **Тексты.** Только из `docs/06_CONTENT_RU.md`. Черновые помечены — не выдавай их за финальные. Если текста нет — заглушка в квадратных скобках `[…]`, не придумывай.
7. **Форма** — единственное целевое действие: имя; бизнес и ссылка; что обсудить (необязательно); канал связи (Telegram / почта / телефон) и контакт; обязательное согласие на обработку ПДн (152-ФЗ) + ссылка на политику. Текст после отправки — **открытый вопрос**.
8. **Нет цен на сайте.** Условие засчёта: 100% стоимости Концепта засчитывается в Воплощение при решении в течение 30 дней.
9. **Без ожидания.** Пользователь не должен ждать, чтобы понять экран: вся важная информация читается сразу, длинные вступления пропускаются касанием/свайпом.
10. **Без параллакса за курсором** (давал «дыры» у краёв). Без вертикального сдвига полноэкранных слоёв без запаса (overscan).

## Обязательные проверки (Definition of Done)

Перед каждым коммитом, который трогает вёрстку/анимации — `docs/07_QA.md`:

- **Нет щели у краёв кадра (особенно сверху)** ни на одном экране и ни в одном размере: 1440×900, 1280×720, 1920×1080, 390×844, 375×667, 430×932. Скрипт: `tools/qa/gapcheck.js` + `gapcheck.py` (или команда `/qa`). Ноль срабатываний — иначе не готово.
- **Экран сайта совпадает с корпусом телефона** на каждом кадре (поворот 04: проверка на 3.7 / 4.1 / 5.4 с).
- **Ничего не налезает на нижнюю строку** («Дальше» / счётчик) на 375×667.
- `prefers-reduced-motion` → переходы 200 мс, вступления пропускаются, смысл сохраняется.
- Lighthouse mobile: Performance ≥ 85, Accessibility ≥ 95. Первая половина грузится мгновенно, тяжёлое (кейсы, поворот) — в фоне.
- Превью ссылки (og:title/og:image) несёт имя и слоган.

## Чего не делать

- Не добавлять страницы «Услуги», «О нас», «Портфолио», FAQ.
- Не возвращать синюю тему «проявленного мира» во втором акте: после поворота сайт тёплый (см. `docs/04_DESIGN_TOKENS.md`). Синий остаётся только в моменте чертежа на повороте.
- Не возвращать «парящие» печенья и уменьшающиеся скриншоты в кейсах — заменены коридором слайдов.
- Не генерировать новые ассеты без согласования (бюджет Higgsfield почти исчерпан, см. `docs/05_ASSETS.md`).
